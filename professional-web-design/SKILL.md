# Professional Web Design

Use this skill to create web interfaces that feel credible, modern, and production-ready rather than obviously AI-generated.

## Core Direction

Design like a serious product team built the interface for real users. Favor clarity, hierarchy, restraint, spacing discipline, useful content density, and domain-appropriate visual choices.

The result should feel:

- Professional
- Trustworthy
- Clean
- Specific to the product
- Easy to scan
- Mature, not playful by default
- Polished without looking decorative

## Avoid AI-Generated Visual Cliches

Do not use:

- Purple/blue neon gradients as the main identity
- Generic glowing orbs, bokeh blobs, mesh gradients, or abstract background waves
- Overly rounded oversized cards everywhere
- Cartoon mascot icons or childish illustrations
- Random floating shapes as decoration
- Generic "AI brain," robot, sparkle, magic wand, or circuit imagery unless the product truly requires it
- Glassmorphism panels with heavy blur
- Big empty hero sections that look like SaaS templates
- Vague marketing copy such as "unlock the power of AI"
- Fake dashboards inside decorative browser mockups unless requested
- Identical card grids with generic icons and shallow text
- One-color themes where every surface is a tint of the same hue
- Oversized typography inside compact UI elements

## Visual Style Rules

### Color

Use a restrained, professional palette with neutral foundations and 1 to 2 purposeful accent colors.

Prefer:

- Warm or cool neutrals for backgrounds
- High-contrast text
- Muted accent colors for actions and status
- Semantic colors for success, warning, danger, and info
- Subtle borders instead of heavy shadows

Avoid palettes dominated by:

- Purple gradients
- Electric blue
- Beige-only editorial tones
- Dark navy everywhere
- Brown/orange coffee themes

### Typography

Use mature, readable typography.

Prefer:

- Professional sans-serif fonts such as Lato, Outfit, Inter, IBM Plex Sans, Source Sans 3, Manrope, Avenir, or similar mature product fonts
- System fonts when external fonts are not available
- Clear type scale
- Strong but restrained headings
- Comfortable line height
- No negative letter spacing
- Text that fits its container at all responsive sizes

Avoid:

- Decorative fonts
- Cartoonish typefaces
- Excessive font weights
- Giant headings in dashboards or forms
- Tiny low-contrast body copy

### Layout

Build layouts around the user's actual workflow.

Prefer:

- Clear page structure
- Strong alignment
- Consistent spacing
- Useful information density
- Predictable navigation
- Responsive grids with stable dimensions
- Full-width sections or tool surfaces instead of nested cards

Avoid:

- Cards inside cards
- Excessively spacious marketing layouts for operational tools
- Repeating generic feature blocks when a real product workflow would be better
- Layouts where visual decoration competes with the task

### Components

Use familiar, production-grade controls.

Prefer:

- Icon buttons for common actions
- Menus for option sets
- Tabs for view switching
- Segmented controls for modes
- Toggles or checkboxes for binary settings
- Sliders, steppers, or inputs for numeric settings
- Tables for structured business data
- Status badges with restrained colors
- Empty states that help users take the next step

Avoid:

- Invented controls when standard controls fit
- Text-heavy buttons for icon-standard actions
- Decorative cards pretending to be controls
- Unclear hover-only interactions

## Content Rules

Write specific interface copy that matches the product.

Prefer:

- Concrete labels
- Plain action text
- Business-specific field names
- Direct error messages
- Short helper text only when it reduces confusion

Avoid:

- Generic AI hype
- Long explanatory text inside the app
- Telling users how polished or powerful the product is
- Filler sections that do not support the workflow

## Product-Specific Guidance

For SaaS, CRM, lead generation, scraping, analytics, admin, or data tools:

- Prioritize the working interface over a marketing hero.
- Make the first screen useful.
- Use tables, forms, filters, status indicators, and exports where appropriate.
- Keep visual design quiet and efficient.
- Use professional icons from an established icon set such as Lucide.
- Make data states clear: pending, running, failed, completed, exported.
- Design for repeated daily use, not only first impressions.

For landing pages:

- Use the product, brand, or offer as the first-viewport signal.
- Use real product UI, relevant screenshots, generated realistic imagery, or concrete workflow visuals.
- Keep hero copy specific.
- Leave a visible hint of the next section on desktop and mobile.
- Avoid fake abstract AI backgrounds.

## Implementation Checklist

Before finalizing frontend work, verify:

- The page does not look like a generic AI template.
- The color palette is not dominated by purple, neon blue, or abstract gradients.
- The typography is readable and mature.
- Buttons, inputs, tables, and cards have consistent sizing.
- Text does not overflow or overlap on mobile or desktop.
- The first screen shows the actual product experience where appropriate.
- Empty, loading, error, and success states are designed.
- Icons are professional and purposeful, not cartoonish.
- The interface supports the user's real workflow.
- Spacing and alignment are consistent.

## Practical Defaults

When the user gives no brand direction, use:

- Background: near-white or very light neutral
- Text: dark neutral
- Borders: subtle neutral
- Primary accent: restrained blue, green, teal, or slate
- Secondary accent: used sparingly for status or highlights
- Font: Lato, Outfit, Inter, IBM Plex Sans, Source Sans 3, Manrope, or the closest available mature sans-serif
- Border radius: 6px to 8px for cards and controls
- Shadows: subtle or none
- Icons: Lucide or existing project icon library
- Layout: product-first, workflow-first

## Final Review Standard

Ask: "Would this look credible if it were shipped by a real startup or business software team?"

If the answer is no, reduce decoration, improve hierarchy, make the content more specific, and bring the design closer to the product's actual workflow.
